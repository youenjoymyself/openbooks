# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

OpenBooks downloads eBooks from the `#ebooks` channel on irc.irchighway.net. It has three modes: desktop (default command), web server (`server`) and terminal (`cli`). This repo is a fork of evan-buss/openbooks.

## Commands

The Go server embeds the built React client (`//go:embed app/dist` in `server/routes.go`), so **build the client before any Go build, vet or test**:

```sh
cd server/app && npm ci && npm run build && cd ../..
go build ./...
go vet ./...
go test -race ./...
go test ./core -run TestClassify -v          # single test
```

Requires Go 1.26+ (see `go.mod`). [Task](https://taskfile.dev) wraps common workflows:

- `task dev:mock`: start the mock IRC/DCC server (IRC `:6667`, DCC `:6668`/`:6669`).
- `task dev:server` / `task dev:cli` / `task dev:desktop`: run against the mock with nickname `dev`. Override it with `NAME=<nick>`; args after `--` are passed through (ex. `task dev:cli -- download '!Server Book.epub'`).
- `task dev:client`: Vite dev server on `127.0.0.1:5173`. In dev mode the client talks to the Go server on port 5228 (`server/app/src/state/util.ts`).
- `task dev:test`: vet plus race tests.
- `task release:build`: cross-compiled release binaries in `build/`.

The desktop WebView GUI needs `-tags webview` (cgo). Without the tag, desktop mode just opens the system browser (`desktop/`).

## Architecture

The packages are layered and each depends only on the ones before it:

1. **`irc/`**: the raw IRC connection.
   - `Conn` owns a shared `bufio.Reader`, so registration (`core.Join`) and the event loop (`core.StartReader`) read the same stream without losing buffered lines.
   - `ParseMessage` splits a line into prefix/command/params.
   - All writes go through `writeLine`, which strips CR/LF/NUL to prevent IRC command injection.
   - `Nick()` tracks the server-confirmed nick (001 and NICK messages).
   - TLS is verified first, then falls back to unverified with a logged warning. IRCHighway's certificate always fails verification, so the warning is expected.
2. **`dcc/`**: parses `DCC SEND` strings and downloads files over TCP.
3. **`core/`**: IRCHighway-specific logic.
   - `Join` waits for 001 and end of MOTD, answers PING and VERSION, and retries taken nicks as `nick_1`…
   - `StartReader` parses each line, answers PING itself, and passes everything else to `classify`.
   - `classify` maps messages to `event` constants and dispatches them to an `EventHandler` (`map[event]HandlerFunc`). Each handler runs in its own goroutine.
   - `DownloadExtractDCCString` downloads to `<name>.temp`, extracts single-file archives (`util/archiver.go`), then renames the result.
   - `search_parser.go` parses search result files; `server_parser.go` parses the NAMES list (users with mode prefixes are the download servers).
4. **Two front ends** implement the same `core.EventHandler`: `server/irc_events.go` (websocket) and `cli/handlers.go` (terminal). A new IRC event needs a constant and a branch in `core/reader.go`'s `classify`, plus handlers registered in both front ends.

`cmd/openbooks/` holds the cobra commands. The root command is desktop mode: it binds `127.0.0.1` and forces persist, with browser downloads disabled. Global flags (`--name`, `--server`, `--tls`, …) are persistent flags on the root command and are copied into each mode's config (`bindGlobalServerFlags`, `cliCmd.PersistentPreRun`).

### Server mode

- Only **one websocket client** may be connected at a time (`addClient` / `canConnect`).
- **Client lifecycle** (`server/client.go`):
  - Each client gets its own IRC connection, plus a `ctx`/`cancel` pair and `readPump`/`writePump` goroutines.
  - Always queue messages with `c.send(msg)`. Never write to or close `c.outbox` directly: IRC handlers keep running after the browser disconnects, and `send` drops messages once `ctx` is cancelled.
  - `readPump` cancels the context *before* disconnecting IRC, so the reader treats the disconnect as intentional and doesn't fire the `Disconnected` event.
- **Shared state:** `server.clients` is guarded by `clientsMutex`, and `Repository` (the server list) by its own mutex.
- **Websocket protocol:** `{type, payload}` JSON. The `MessageType` and `NotificationType` enums in `server/messages.go` must stay in sync with `server/app/src/state/messages.ts`. `messagetype_string.go` is generated by `stringer`.
- **Files:** saved under `<dir>/books`. Without `--persist`, a book is deleted after the browser downloads it from `/library/*`.

### Security invariants (regression-tested)

- **DCC offers:** only accepted as a CTCP `PRIVMSG` addressed to our own nick. Channel messages and plain text are ignored, because anyone in `#ebooks` can post text.
- **File names** from remote peers are reduced to a single path element before they touch disk: `dcc.sanitizeFilename`, `util.entryFileName`, and `isPlainFileName` in `server/routes.go`.
- **Archives are detected by file extension only** (`util.extractorFor`). Content sniffing would treat `.epub` files as zip archives and extract them.
- **Websocket origins:** `server.checkOrigin` only allows the server's own host, `X-Forwarded-Host`, the Vite dev origin, or `--allowed-origins`.

### IRC conventions to preserve

- **CTCP VERSION reply** (`core.SendVersionInfo`): the reply is `\x01<useragent>\x01`, without the `VERSION` keyword. `ircVersion` in `cmd/openbooks/main.go` is only bumped when the IRC admins require it, because they allow or block specific versions. Don't change either without a reason from them.
- **Search rate limit:** searches are limited to one every 10 seconds at minimum, to protect the search bots.

## Testing notes

- `mock/` provides `DccServer` and `IrcServer`. The DCC tests bind fixed local ports (6969–6972), so pick a new port for new tests.
- `core/irchighway_test.go` has `fakeServer`/`expect` helpers for scripting an IRC server conversation.
- `core/search_parser_test.go` uses real search output (`sampleData`); every line in it is expected to parse.
- Run the mock binary from `cmd/mock_server/`, because it opens its sample files by relative path.

## CI and Docker

- `.github/workflows/test.yml` builds the client, then runs vet and race tests on every push and PR.
- The docs deploy (`docs.yml`, MkDocs to GitHub Pages) only runs when triggered manually; Pages isn't enabled on this fork.
- Docker images go to GHCR, and to Docker Hub only if the `DOCKERHUB_IMAGE` repository variable is set.
- The `Dockerfile` builds the web assets and cross-compiles the Go binary on the build platform. The image runs `openbooks server --dir /books --port 80`.
